# Конспект сессии: Асинхронная загрузка тяжелых компонентов (Lazy Loading) в Nuxt 3

## Проблема
Пользователь обратился с запросом провести аудит производительности (frontend и backend) и выявить значимые возможности для ускорения приложения. 

В ходе анализа архитектуры было обнаружено, что тяжелые компоненты — визуализатор графа знаний (`KnowledgeGraphVisualizer.vue`, использующий библиотеку `d3`) и просмотрщик PDF (`ThePdfViewer.vue`, использующий `pdfjs-dist`) — импортировались в приложение **синхронно**. Это приводило к тому, что огромные куски JavaScript попадали в начальный бандл (Initial Chunk). В результате браузер скачивал и парсил мегабайты лишнего кода при первой загрузке главной страницы, даже если пользователь не заходил в разделы с графом или презентациями. Это серьезно ухудшало показатели Time to Interactive (TTI) и Largest Contentful Paint (LCP) на слабых устройствах.

## Решение
Для разгрузки стартового бандла была применена стратегия отложенной (ленивой) загрузки компонентов.

Вместо ручного написания оберток через Vue 3 `defineAsyncComponent`, мы использовали встроенную возможность автоимпорта Nuxt 3: добавление префикса `Lazy` к имени компонента в шаблоне.

Произведена замена тегов:
- `<KnowledgeGraphVisualizer>` на `<LazyKnowledgeGraphVisualizer>`
- `<ThePdfViewer>` на `<LazyThePdfViewer>`

Изменения затронули 7 ключевых локаций:
1. Главная страница графа знаний (`pages/knowledge-graph.vue`).
2. Окно InPlaceEditor в админке (`components/admin/WorkspaceEditor.vue`).
3. Панель синхронизации для предпросмотра JSON (`pages/admin/sync.vue`).
4. Предпросмотр импорта ODT/JSON на страницах `glossary`, `books` и `articles`.
5. Просмотр PDF-презентаций в статьях (`components/thePresentationView.vue`).

Теперь скрипты `d3` и `pdfjs-dist` скачиваются асинхронным чанком только тогда, когда условие рендера (например, открытие попапа или переход на страницу) выполняется.

## Извлеченные уроки и ловушки

1. **Магия Nuxt 3 Lazy-компонентов**:
   > Nuxt 3 автоматически генерирует асинхронные обертки для всех компонентов в папке `components/`. Использование префикса `Lazy...` (например, `<LazyThePdfViewer>`) — это самый чистый и безопасный способ внедрить `defineAsyncComponent` без изменения секции `<script setup>` и нарушения типизации свойств (props).
2. **Риски глубокой реактивности (`shallowRef` vs `ref`)**:
   > В ходе мозгового штурма предлагалась оптимизация реактивности: замена `ref` на `shallowRef` для огромных массивов (тысячи узлов графа или терминов глоссария), чтобы избежать "реактивного шторма" (Reactivity Thrashing) от геттеров/сеттеров Vue. 
   > **Ловушка**: Интеграция `shallowRef` в уже готовую сложную архитектуру сопряжена с огромным риском "сломать" неявные зависимости и мутации данных в дочерних компонентах. Пользователь принял мудрое решение отказаться от этой идеи. Ленивая загрузка (Lazy Loading) дала максимум профита (загрузка бандла) при нулевом риске регрессий, тогда как `shallowRef` мог привести к рассинхронам UI и хранилища.
3. **UX при ленивой загрузке**:
   > При асинхронной загрузке компонентов по сети может возникнуть задержка (доли секунды на слабом интернете), прежде чем компонент отрисуется. В данном проекте это поведение органично замаскировалось существующими спиннерами и флагами `pending / graphInitializing`, поэтому дополнительные скелетоны (`<Suspense>`) не потребовались.
