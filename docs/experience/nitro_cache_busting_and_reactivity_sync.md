# Синхронизация реактивности Vue и инвалидация серверного кэша Nitro (unstorage)

## Проблема
Во время редактирования статьи через встроенный in-place редактор (`AdminArticleForm`), после успешного сохранения изменений и закрытия редактора, в DOM (основной просмотр статьи) отображалась старая, закэшированная версия текста.

Исследование выявило двойную проблему кэширования:
1. **Бэкенд (Nitro/unstorage):** Логика ручного сброса кэша при обновлении сущностей (статьи, книги, термины) не работала. Использовался вызов `storage.getKeys('nitro:handlers:articles:slug')`, который воспринимал аргумент как базовую папку и возвращал пустой массив, из-за чего кэшированные JSON-файлы с ответами оставались в памяти.
2. **Фронтенд (Браузерный кэш + Nuxt Payload):** Даже после очистки кэша на сервере, браузер продолжал перехватывать GET-запросы от `useAsyncData` (вызываемые через `refresh()`) и возвращал ответ из собственного `disk cache`, так как изначально сервер отправлял заголовок `Cache-Control: max-age=3600`. Дополнительно, компонент закрывался быстрее, чем Vue успевал получить и отрендерить новые данные.

## Решение

### 1. Серверная инвалидация кэша (unstorage)
Вместо фильтрации на уровне `getKeys`, был применен метод получения всех ключей для базового пространства имен (`nitro:handlers:articles/books/terms`) с последующей ручной фильтрацией через `.startsWith()`:
```typescript
const clearKeysForSlug = async (s: string) => {
  const keys = await storage.getKeys('nitro:handlers:articles') // Запрашиваем всю "папку"
  const prefix = `nitro:handlers:articles:${s}_role_`
  for (const key of keys) {
    if (key.startsWith(prefix) || key.startsWith(`nitro:handlers:articles:${s}.json`)) {
      await storage.removeItem(key)
    }
  }
}
```
Для дополнительной надежности и удобства редакторов, в эндпоинты `GET` (`articles`, `books`, `terms`) добавлена функция `shouldBypassCache`. Теперь пользователи с ролями `admin` и `editor` всегда обходят кэш сервера и читают актуальные данные напрямую из БД.

### 2. Клиентский Cache-Buster и бесшовная перерисовка
Чтобы обойти агрессивное кэширование браузера (возникающее из-за `max-age=3600`), в параметры запроса `useAsyncData` добавлен уникальный временной маркер `_t: Date.now()`, который применяется только на клиенте (`import.meta.client`). Это гарантирует, что браузер посчитает URL уникальным и отправит реальный сетевой запрос.

Для бесшовного скрытия редактора и мгновенного отображения нового текста, функция-обработчик сохранения (`onInlineSaved`) была сделана асинхронной:
```typescript
async function onInlineSaved() {
  clearNuxtData(`article-${slug.value}`) // Сбрасываем payload Nuxt
  await refresh()                        // Ждем завершения сетевого запроса и обновления articleData
  isEditingInPlace.value = false         // Закрываем редактор только когда DOM под ним уже обновлен
}
```

## Извлеченные уроки (Gotchas)
- **Nuxt/Nitro Unstorage:** Функция `storage.getKeys(base)` работает строго как поиск по директориям. Если передать туда часть конкретного ключа (например, содержащую двоеточия или параметры), она ничего не найдет. Необходимо запрашивать общую родительскую директорию (например, `nitro:handlers:articles`) и фильтровать массив ключей в коде.
- **Cache-Control vs useAsyncData:** Даже если `useAsyncData` принудительно вызывает `$fetch` с заголовком `Cache-Control: no-cache`, некоторые браузеры все равно могут вернуть ответ из локального дискового кэша, если оригинальный ресурс имел большой `max-age`. Самый надежный способ пробить браузерный кэш для GET-запросов — динамический query-параметр (cache-buster).
- **Vue Reactivity Sync:** Если при закрытии компонента-редактора полагаться только на синхронные вызовы и не использовать `await` для функции получения данных (`refresh`), интерфейс "моргнет" старыми данными перед тем, как подгрузятся новые. Явная очистка стейта через `clearNuxtData` вкупе с `await refresh()` создает идеальный бесшовный UX.
