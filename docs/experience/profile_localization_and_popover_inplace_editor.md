# Локализация профиля и бесшовное In-Place редактирование из попапов

## Проблема
1. **Профиль и Локализация:** Компонент панели администратора (`theAdministration.vue`), находящийся в профиле, был написан с хардкодом русских строк. При переключении языка (например, на английский или китайский) данный виджет не менялся, в то время как весь остальной профиль был локализован. Это нарушало целостность мультиязычного интерфейса.
2. **Бесшовное редактирование у попапов:** Требовалось расширить логику редактирования "на ходу" (In-Place Editor). Ранее эта возможность была доступна только в виде фиксированной плавающей кнопки на страницах статей/книг. Необходимо было внедрить её прямо в `theTermPopover.vue` (всплывающую подсказку термина/статьи), чтобы редакторы могли инициировать редактирование, не переходя на отдельную страницу.

## Решение
1. **Локализация `theAdministration.vue`**:
   - Внутри компонента создан локальный словарь `uiDict` (с ключами `en`, `ru`, `zh`).
   - Использован `langStore.currentLang` для реактивного переключения языка.
   - Заменены все хардкодные строчки в шаблоне и скрипте (названия ролей, описание, статистика, KPI).
   - Форматирование даты (`lastArticleUpdatedAt`) также было привязано к языковому контексту через вызов `toLocaleString(locale)` с передачей нужной локали (`ru-RU`, `zh-CN`, `en-US`).
   
2. **Рефакторинг `InPlaceEditor.vue`**:
   - Чтобы переиспользовать сложную логику Slideover'а с динамической подгрузкой компонентов форм (`WorkspaceEditor`, `AdminArticleForm`, `AdminBookForm`), мы модифицировали `InPlaceEditor.vue`.
   - Вынесли плавающую кнопку (trigger) в `<slot name="trigger" :open="openEditor">`.
   - Добавили пропс `wrapperClass` со значением по умолчанию (старые стили фиксированной кнопки), чтобы не сломать предыдущие внедрения компонента на других страницах.

3. **Внедрение в `theTermPopover.vue` и `KnowledgeGraphVisualizer.vue`**:
   - В `popover-footer` интегрирован `<InPlaceEditor>` для случаев, если открыт конкретный термин, статья или книга (с условием наличия `term.id` или `selectedNode.id`).
   - Внутри слота `#trigger` размещена компактная иконка `i-heroicons-pencil-square`, завёрнутая в тултип (с поддержкой перевода).
   - Таким образом, при наведении на термин (или клике на узел в графе знаний) редактор видит попап, в подвале которого есть кнопка "Редактировать". Клик по ней открывает In-Place Editor поверх всего окна, позволяя бесшовно изменить сущность, не ломая навигацию.

## Извлеченные уроки и нюансы
- **Гибкость паттерна со слотами**: При использовании `v-slot` для кастомизации кнопок триггеров (trigger buttons), оказалось полезно прокидывать класс обертки через пропс `wrapperClass`. За счет `wrapperClass="mr-auto flex shrink-0"` удалось легко прижать кнопку редактирования к левому краю футера попапа, сохранив отступы для других ссылок с правой стороны (построенных на `justify-content: flex-end`).
- **Ленивая загрузка**: В `InPlaceEditor` продолжает эффективно работать связка `<Suspense>` и динамически импортируемых тяжелых админских форм. Так как теперь `InPlaceEditor` инжектируется в каждый попап (который создается в теле документа), ленивая инициализация критически важна: формы не рендерятся и не грузят публичный UI до тех пор, пока пользователь не нажмет на "Карандаш".
- **Решение проблемы наложения слоёв (z-index)**: При внедрении `USlideover` (панели редактора) внутрь компонента попапа с очень высоким `z-index` (100000), попап перекрывал саму панель редактора. Мы отказались от глобального повышения `z-index` для редактора (так как это сломало бы внутренние выпадающие списки `USelectMenu`), а вместо этого заставили `InPlaceEditor` эмитить событие `@update:isOpen`. Получая этот сигнал, попап просто прячет себя (`opacity: 0, pointerEvents: 'none'`), оставаясь смонтированным в DOM и не мешая редактированию.
- **D3 Graph Node ID vs Database ID**: Внутри `KnowledgeGraphVisualizer` идентификаторы узлов модифицируются для уникальности в SVG (например, `art-15`, `book-2`). При передаче идентификатора узла в `InPlaceEditor` критически важно использовать `node.originalId` (в котором хранится чистый ID базы данных), иначе API-запросы редактора на получение данных сущности вернут ошибку 404.
