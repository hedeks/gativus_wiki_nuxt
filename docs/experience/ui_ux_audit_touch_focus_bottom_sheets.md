# Улучшение UX: Touch-таргеты, Bottom Sheets и Focus-стейты

## Проблема
Пользователь инициировал аудит UX дизайна и попросил улучшить общий опыт использования интерфейса. Основные боли заключались в:
1. Отсутствии автоматического скролла оглавления (`TheToc`) на длинных страницах (articles/slug), из-за чего активная глава пропадала из виду.
2. Слишком мелких элементах управления на мобильных устройствах (иконки, пагинация, ссылки оглавления), что усложняло взаимодействие пальцем.
3. Неудобном поведении выпадающих меню (язык, фильтры) на мобильных — они открывались как классические дропдауны, вместо привычных мобильных Bottom Sheets (шторок).
4. Отсутствии визуального отклика (focus-rings) при навигации по сайту с помощью клавиатуры (Tab) для кастомных элементов (например, внутри оглавления).

## Решение

### 1. Авто-скролл для `TheToc`
В компоненте `theToc.vue` был добавлен `ref` на контейнер со скроллом и `watch` за `props.activeID`. При смене активной главы вызывается метод `activeElem.scrollIntoView({ behavior: 'smooth', block: 'nearest' })` через `nextTick`. Это элегантно решает проблему, сохраняя активный элемент в зоне видимости без резких скачков.

### 2. Мобильные Bottom Sheets для дропдаунов
Для компонентов `AnchoredMenuDropdown` (используется в `LanguageSwitcher` и профиле) и `ExpandableFilters` (используется в `TheSearch`) была написана специальная CSS/JS-логика:
- При ширине экрана `<= 640px` (или `<= 639px`) инлайн-стили позиционирования (`top`/`left`) перезаписываются через `!important` или меняются программно на `bottom: 0`, `left: 0`, `width: 100vw`.
- Добавлено закругление только верхних углов (`border-radius: 20px 20px 0 0`).
- Внедрен слой `backdrop-blur-sm` (background `bg-black/20`) позади меню, чтобы сфокусировать внимание на контенте шторки, и по клику на который модальное окно закрывается.
- Транзишены переделаны на выезд снизу (`transform: translateY(100%)`).

### 3. Улучшение Touch-таргетов
В `GvPagination.vue`, `theToc.vue` и `theTocItem.vue` минимальная высота интерактивных элементов (`min-height`) была увеличена до 44px через медиа-запросы для мобильных устройств, что соответствует лучшим практикам Apple/Google (не менее 44x44 pt).

### 4. Поддержка клавиатуры (Focus-стейты)
- Глобальный класс `.gv-focusable:focus-visible` (определенный в `app.vue` как `outline: 2px solid var(--gv-primary); outline-offset: 2px;`) был интегрирован в ссылки и кнопки.
- Для `div`-элементов внутри `theTocItem.vue` (которые ведут себя как кнопки) был добавлен `tabindex="0"`, а также слушатели событий `@keydown.enter` и `@keydown.space.prevent`. Это позволило полностью управлять оглавлением без использования мыши.

## Извлеченные уроки
- **CSS-специфичность и инлайн-стили**: Если дропдаун (как `AnchoredMenuDropdown`) позиционируется через JS инлайн-стилями, перебить их из CSS можно только через `!important`. В таких ситуациях лучше либо полностью отключать инлайн-расчет позиций для мобильных (как было сделано в `ExpandableFilters` через `if (vw <= 640)`), либо агрессивно применять `!important` внутри `@media (max-width: 640px)`. 
- **Touch-таргеты и Layout Shift**: При увеличении `min-height` до 44px на мобильных устройствах элементы могут менять общую высоту блока. Чтобы избежать layout shift или некрасивых отступов, лучше использовать `padding: 4px 12px` или `min-height` вместо жесткого `height`.
- **Keyboard A11y**: При использовании кастомных `<div>` как кнопок, недостаточно просто добавить класс `:focus-visible`. Элемент должен иметь `tabindex="0"` и обязательно обрабатывать `@keydown.enter` и `@keydown.space` (с модификатором `.prevent` во избежание скролла страницы вниз при нажатии пробела).
