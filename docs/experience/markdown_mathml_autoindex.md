# Опыт: Импорт Markdown, MathML из ODT и Авто-нумерация заголовков

## Проблема
Пользователь обратился с задачей реализовать полноценную поддержку Markdown (.md) файлов с парсингом LaTeX Math (через KaTeX), а также извлечение математических формул из ODT-документов.
Кроме того, возникла сопутствующая проблема: при загрузке Markdown-файлов не работала системная переиндексация глав, так как Markdown-парсер не генерировал специальные ODT-маркеры.

## Решение
1. **Импорт Markdown и обработка изображений**:
   - Использован пакет `markdown-it` с плагином `markdown-it-katex` для парсинга текста и формул.
   - Написан парсер `server/utils/mdParser.ts`, который работает с `.md` и `.zip` архивами.
   - Если в Markdown-файле найдены локальные ссылки на изображения (которых нет на сервере), сервер возвращает их массив (`missingImages`).
   - Во Vue-редакторе (`AdminArticleWysiwyg.vue`) реализована премиальная (Luxe-класса) модалка. Пользователь видит список недостающих изображений и может загрузить их пошагово прямо через браузер, после чего они автоматически подставляются в HTML.

2. **Извлечение MathML из ODT**:
   - В `server/utils/odtParser.ts` добавлена поддержка OLE-объектов (`<draw:object>`). Парсер достает вложенный файл `Object X/content.xml` из ZIP-структуры ODT.
   - Из него извлекается `<math:math>` (MathML), очищается от неймспейсов и вставляется в итоговый HTML напрямую как HTML5 `<math>` тег (поддерживается современными браузерами).
   - В случае неудачи (например, старый формат) срабатывает фоллбэк: берется готовое изображение из `ObjectReplacements/`.

3. **Авто-нумерация и иерархия заголовков**:
   - В `mdParser.ts` настроен сдвиг заголовков. Парсер находит самый первый `h1`, вырезает его из контента и отправляет в системное поле `title`. Все остальные заголовки (`h1`, `h2`, `h3` и т.д.) сдвигаются на один уровень вниз (`h1 -> h2`). Это сохраняет SEO-структуру (один `<h1>` на страницу) и гарантирует единообразие с ODT-парсером.
   - В `server/utils/reindexHeadingMarkers.ts` создана мощная утилита `autoIndexHeadings`, а в API `reindex.post.ts` добавлен режим `auto_index`. Теперь встроенный редактор умеет автоматически с нуля пронумеровывать все заголовки (`h2`, `h3`, `h4`) по порядку их вложенности (Глава 1, 1.1, 1.1.1 и т.д.), предварительно очищая их от старых системных маркеров или введенных вручную цифр.

## Извлеченные уроки
- **Менеджмент Markdown-AST**: Для сдвига заголовков и вырезания первого `h1` самым гибким и надежным подходом оказалась модификация самого массива `tokens` (AST) до вызова `md.renderer.render(tokens)`, а не попытка парсить итоговый HTML строковыми регулярками.
- **Интерактивная загрузка медиа**: Вместо того чтобы принуждать пользователя обязательно архивировать Markdown вместе с картинками в ZIP перед загрузкой, создание интерактивного UX-процесса с модальным окном (где отсутствующие локальные картинки подгружаются "на лету" из файловой системы пользователя) сделало систему значительно дружелюбнее.
- **Универсальная авто-нумерация**: Изначально предполагалось, что Markdown должен генерировать ODT-маркеры при парсинге. Но решение вынести функцию "Авто-нумерация с нуля" в отдельную кнопку переиндексации оказалось гораздо эффективнее, так как это решило проблему не только для импортированного Markdown, но и для статей, которые пользователи пишут вручную во встроенном WYSIWYG-редакторе.
