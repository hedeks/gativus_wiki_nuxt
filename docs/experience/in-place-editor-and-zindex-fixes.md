# Внедрение In-Place Редактора и Исправление z-index Модальных Окон

## Проблема
Пользователь запросил функционал редактирования контента "на лету" (без перехода в админ-панель) для всех сущностей (статьи, термины, книги). 
Основные требования:
- Редактор должен появляться прямо на месте текстового блока статьи ("in-place" без перекрытия экрана).
- Должна сохраняться возможность вызова боковой панели (Side Panel) для редактирования дополнительных метаданных.
- Интерфейс редактора должен быть полностью скрыт на мобильных устройствах.
- При разработке выявилась проблема: встроенные в редактор модальные окна Nuxt UI (`AdminMediaPicker`, выбора терминов и т.д.) перекрывались панелью `USlideover`, так как и те, и другие имели стандартный или конфликтующий `z-index`.

## Решение
1. **Реализация плавающего редактора (InPlaceEditor)**:
   - Разработан компонент `InPlaceEditor.vue`, выводящий плавающую кнопку в правом нижнем углу для авторизованных пользователей (роли `editor`/`admin`).
   - Кнопка вызывает `USlideover`, внутри которого переиспользуются формы из админки (`AdminArticleForm`, `WorkspaceEditor`, `AdminBookForm`).
   - На мобильных устройствах плавающая кнопка и кнопка инлайн-редактирования полностью скрыты с помощью утилит Tailwind (`hidden md:flex`, `hidden md:block`).

2. **In-Place редактирование статей**:
   - На странице `articles/[slug].vue` добавлена кнопка "Редактировать" рядом с заголовком.
   - Компонент `AdminArticleForm.vue` доработан с введением свойства `inlineMode`. При активации скрывается левый сайдбар и шапка, а сам редактор `AdminArticleWysiwyg.vue` разворачивается на всю ширину и высоту (`height: calc(100vh - 4rem)`). Режим по умолчанию установлен в `preview` (визуальный WYSIWYG).
   - Это решение позволило избежать дублирования сложной логики сохранения контента статьи.

3. **Исправление z-index конфликтов в Nuxt UI**:
   - С `USlideover` в `InPlaceEditor.vue` убран жесткий класс `z-[100]`, возвращен стандартный `z-index: 50`.
   - Всем зависимым модальным окнам (`AdminMediaPicker` — превью и галерея, `TermSelectorModal`, `BookSelectorModal`, `ArticleSelectorModal`) было принудительно задано свойство `:ui="{ wrapper: 'z-[200]' }"`. Это гарантирует их вывод поверх любых слайдоверов или плавающих элементов.

## Извлеченные уроки
1. **Z-Index и Nuxt UI (Headless UI)**: При вложении множества слоев (Слайдовер -> Модалка -> Галерея) стандартное позиционирование `Teleport` к `body` может привести к скрытию окон друг под другом, если не контролировать свойство `wrapper` в `ui` пропсах. Всегда используйте безопасные шаги (например, `z-[200]`) для модальных окон верхнего уровня, чтобы они гарантированно выводились поверх `USlideover`.
2. **Переиспользование админских форм (Монолиты vs Микро-компоненты)**: Вместо того чтобы дублировать логику сохранения статей (PUT-запросы, реактивные переменные, привязка словарей) на публичной странице `articles/[slug].vue`, добавление флага `inlineMode` в `AdminArticleForm.vue` оказалось наиболее выгодным по трудозатратам и поддерживаемости кодовой базы решением. 
3. **MCP Обновления**: При работе с файловой системой через MCP для ИИ-агентов стоит требовать (через промпт-правила проекта) использования **только абсолютных путей**, чтобы избежать багов с относительными путями в среде `Claude Desktop`.
