# Опыт внедрения Массовых (Bulk) эндпоинтов и макро-инструментов MCP

## Проблема
Изначально в проекте Gativus Wiki присутствовали только атомарные (CRUD) эндпоинты. ИИ, работая через MCP, при необходимости обновить или удалить 50 статей вызывал инструмент `patch_article` 50 раз подряд в цикле, что приводило к перегрузке сервера, таймаутам и неконтролируемым ошибкам.
Также глобальная перелинковка `global_relink_terms` была слишком тяжелой, и ИИ вызывал её даже при добавлении одного термина.

## Решение
1. **Универсальные Bulk-эндпоинты:**
   - Созданы `server/api/admin/articles/bulk.patch.ts` и `server/api/admin/articles/bulk.delete.ts`.
   - Аналогичные эндпоинты созданы для терминов (`terms/bulk.patch.ts`, `terms/bulk.delete.ts`) и книг (`books/bulk.delete.ts`).
   - Эти эндпоинты принимают массив `ids` и применяют изменения разом с помощью SQL `WHERE id IN (...)`.

2. **Умная перелинковка одного термина (`relink-term/[id]`):**
   - Создан мощный инструмент для перелинковки только одного термина.
   - **Алгоритм (Ловушка/Нюанс):** Нельзя просто стереть все ссылки в статье и заново прилинковать один термин, так как это удалит все остальные термины. Поэтому мы используем SQL `LIKE` для поиска всех статей, содержащих слаг или алиасы нужного термина, и только для них запускаем полный цикл перелинковки. Это в сотни раз быстрее глобальной перелинковки, но при этом сохраняет консистентность.

3. **Ограничения ИИ через контекст и MCP:**
   - Инструменты MCP теперь содержат строгие описания (`describe()`) с предупреждениями (например, `WARNING: IRREVERSIBLE`).
   - Метод `get_all` теперь предупреждает о большом объеме данных и рекомендует `global_search`.
   - В `mcp-adapter/gativus-context.md` прописан раздел "Атомарные vs Массовые операции (Bulk)", запрещающий ИИ использовать атомарные методы в цикле.

## Извлеченные уроки (Best Practices)
- **Zod Descriptions:** Описания в Zod-схемах MCP (`z.describe()`) работают как мощный предохранитель. ИИ читает их каждый раз при планировании. 
- **SQL LIKE для оптимизации:** Использование `LOWER(html_content) LIKE '%term%'` оказалось ключом к ускорению точечных перелинковок без разрушения остального графа связей.
- **Очистка связей перед удалением:** В эндпоинтах `bulk.delete.ts` важно не забывать очищать сводные таблицы (например, `article_terms` или `book_categories`) перед удалением основных записей.
